## What is a trade-off ?

A trade-off occurs when improving one architectural quality (pillar) negatively impacts another, requiring a deliberate balance between competing concerns.
## The need for compromise

A system cannot maximize all quality attributes at once; architectural decisions must prioritize certain qualities over others based on business goals and constraints.

The key is finding the right compromise and identity mitigation techniques to satisfy the architecture quality with minimal impacts.

| Trade-off                      | Why it happens                                                                                                                        | How to balance                                                                                                                                                                                                                                                                                               | Mitigation techniques                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Security vs Performance        | Security mechanisms add overhead (encryption, auth checks, logging)                                                                   | Security is a baseline requirement; the level of enforcement should be driven by risk. Prioritize strong protections for sensitive data and critical operations, and optimize performance by applying security controls selectively and using defense-in-depth across application and infrastructure layers. | Use selective [encryption](Concepts/Security/Data%20encryption/README.md), [Caching](Caching.md), [Hardware acceleration](Hardware%20acceleration.md), and optimize critical paths                                                                                                                                                                                                                                        |
| Security vs Maintainability    | Security controls (access restrictions, validation, compliance requirements) increase system complexity and slow down changes         | Security is a baseline requirement; apply controls proportionally to risk, enforcing stricter measures on sensitive components while keeping less critical areas simpler to maintain.                                                                                                                        | Use standard security frameworks, automate security checks ([DevSecOps](DevSecOps.md)), apply clear abstractions, and enforce defense-in-depth without over-engineering                                                                                                                                                                                                                                                   |
| Reliability vs Cost            | High reliability requires redundancy, failover mechanisms, and over-provisioning, which increase infrastructure and operational costs | Align reliability targets with business criticality by applying higher redundancy to critical components while accepting lower guarantees for non-critical workloads, provided they meet business requirements.                                                                                              | Use tiered SLAs, [Autoscaling](Autoscaling.md), spot instances, graceful degradation, and selective redundancy                                                                                                                                                                                                                                                                                                            |
| Simplicity vs Scalability      | Distributed systems introduce coordination, state management, and operational complexity                                              | Prioritize simplicity in early stages, and introduce scalability mechanisms incrementally as demand grows or bottlenecks emerge; design for modularity to enable controlled and incremental scaling.                                                                                                         | Start simple, scale only where needed, and isolate compl - [Module Monolith (aka Modulith)](Module%20Monolith%20(aka%20Modulith).md) : start simple, scale later<br>- [Caching](Caching.md) (reduce need for scaling)<br>- [Horizontal scaling](Horizontal%20scaling.md) (scale replicas before splitting into servicies)<br>- [Strangler Fig](Strangler%20Fig.md) (gradually replaces parts of a monolith with services) |
| Flexibility vs Maintainability | Highly flexible systems are harder to reason about and test                                                                           | Apply flexibility selectively where change is expected, while keeping the rest of the system simple and stable                                                                                                                                                                                               | Use clear abstractions, bounded contexts (DDD), and avoid over-generalization                                                                                                                                                                                                                                                                                                                                             |
| Observability vs Cost          | Logs, metrics, and traces consume storage, compute, and network resources                                                             | Adjust observability depth based on system criticality, increasing visibility where failures have high impact                                                                                                                                                                                                | Sampling, log levels, retention policies, aggregation, and tiered observability                                                                                                                                                                                                                                                                                                                                           |
| Consistency vs Availability    | Strong consistency limits availability in distributed systems (see [CAP Theorem](CAP%20Theorem.md))                                   | Apply strong consistency where correctness is critical, and relax consistency where eventual accuracy is acceptable                                                                                                                                                                                          | Eventual consistency, CQRS, caching, idempotency, retries                                                                                                                                                                                                                                                                                                                                                                 |
| Performance vs Maintainability | Highly optimized code introduces complexity and reduces readability                                                                   | Optimize only critical paths while keeping the majority of the system simple and maintainable                                                                                                                                                                                                                | Profile first, isolate optimizations, document critical paths, and encapsulate complex logic                                                                                                                                                                                                                                                                                                                              |
| Sustainability vs Performance  | Maximizing performance often increases resource consumption and energy usage                                                          | Balance performance and efficiency by optimizing resource usage rather than maximizing raw performance                                                                                                                                                                                                       | Efficient algorithms, right-sizing, workload scheduling, and energy-aware architecture                                                                                                                                                                                                                                                                                                                                    |
