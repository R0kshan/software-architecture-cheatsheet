A reference for common **software architecture terms, abbreviations, and design methods**. Each entry is concise and links to deeper resources.
## Architecture vs Design

| Term / abbreviation     | Definition                                                                                                                                 | For further reading                                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| HLD (High-Level Design) | The **high-level structure of a system**, defining its major components, interactions, external dependencies, and system-wide constraints. | [HLD explained by GeeksForGeeks](https://www.geeksforgeeks.org/system-design/getting-started-with-system-design/) |
| LLD (Low-Level Design)  | Describes **how individual components are implemented**, including class structures, algorithms, and design patterns.                      | [LDD explained by GeeksForGeeks](https://www.geeksforgeeks.org/system-design/getting-started-with-system-design/) |

## Requirements

| Term / abbreviation | Definition                                                                                                                                   | For further reading                                                                          |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| FR                  | **Functional Requirements** d**efine what the system must do** (features and behaviors).                                                     | [NFR by Redhat](https://www.redhat.com/en/blog/nonfunctional-requirements-architecture)      |
| NFR                 | **Non-Functional Requirements** define how the system behaves under constraints such as performance, reliability, security, and scalability. | [NFR blog by Redhat](https://www.redhat.com/en/blog/nonfunctional-requirements-architecture) |
## Service & Operational Terms

| Term / abbreviation | Definition                                                                                                                                                                                               | For further reading                                                            |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| SLA                 | **Service Level Agreement**: A formal contract defining the expected level of service between a provider and a customer, including metrics like uptime, response time, and penalties for non-compliance. |                                                                                |
| SLO                 | **Service Level Objective**: A specific, measurable target for a service’s reliability (e.g., "99.9% uptime").                                                                                           | [Defining slo - Google](https://sre.google/sre-book/service-level-objectives/) |
| SLI                 | **Service Level Indicator**: A quantitative measure of a service’s performance (e.g., "request latency").                                                                                                | [Defining slo - Google](https://sre.google/sre-book/service-level-objectives/) |
| MTTR                | **Mean Time To Repair/Recover**: The average time taken to restore a service after a failure.                                                                                                            |                                                                                |
| MTBF                | **Mean Time Between Failures**: The average time between system failures.                                                                                                                                |                                                                                |
